# Переделка фронтенда: лендинг с 3D и платформа «Чертёж»

**Статус:** на ревью · **Дата:** 2026-10-11 · **Ветка:** `frontend-redesign`

## 1. Зачем и для кого

Нынешний фронт (`frontend/`, React + Vite) — один экран приёма пакета и отчёт. Нужен «официальный», солидный
продукт: отдельный лендинг с анимацией и 3D и удобная платформа для эксперта.

Аудитория лендинга — обе сразу:
- **комиссия на защите и научная аудитория** — метод, метрики, эксперименты;
- **будущие пользователи** — экспертные организации и проектные бюро РК: польза, доверие, «запросить доступ».

Успех:
- посетитель за первый экран понимает, что делает сервис (сцена «Расслоение»);
- демо-отчёт открывается без входа;
- эксперт проходит путь «загрузил → разделы → отчёт → вердикты → XLSX» без подсказок;
- лендинг грузится быстро (бюджеты в §7), сцена не мешает телефонам и режиму «уменьшить движение».

Вне рамок: анализ ТЭП (`src/`), формат отчёта, вход через Supabase — не меняются. Казахский интерфейс
платформы — позже (тексты вынесены в словарь).

## 2. Решения, принятые на обсуждении

| Вопрос | Решение |
|---|---|
| Визуальное направление | **A. «Чертёж»** — официальный стандарт: сетка кальки, синий акцент, красный «карандаш эксперта» |
| 3D первого экрана | **«Расслоение»**: здание в линиях расходится на этажи ПЗ / АР / КР / Смета, расхождение обводится красным |
| Раскладка платформы | **Боковое меню + отчёт в три колонки** (замечания · документы · панель замечания) |
| Блоки лендинга | 9 блоков (§4), порядок как предложен |
| Стек | **Одно приложение Vite + React**: React Router, Tailwind + shadcn/ui (Radix), react-three-fiber, Motion, cmdk, TanStack Query |

Отвергнуто: Next.js (переписывать всё ради SEO, который почти не нужен; сложнее с Python-функцией на Vercel),
Astro + React (две кодовые базы), Spline (1–2 МБ стороннего рантайма, мало контроля над сценой по скроллу).

## 3. Дизайн-система «Чертёж»

**Темы.** «Калька» (светлая, основная) и «Синька» (тёмная). Переключатель в настройках и ⌘K; по умолчанию —
системная тема.

| Токен | Калька | Синька | Смысл |
|---|---|---|---|
| `paper` | `#F4F6F3` | `#0F1E3D` | фон с сеткой 24 px |
| `sheet` | `#FFFFFF` | `#132548` | лист, панели |
| `ink` / `ink-2` | `#1E2A2B` / `#55615E` | `#E6EDF7` / `#A9B8D1` | текст / вторичный |
| `line` / `control` | `#C9D2CD` / `#7F8C87` | `#2A4478` / `#5D77A8` | разделители / рамки элементов (≥ 3:1) |
| `blue` | `#1E3A8A` | `#8FB4FF` | действия, ссылки |
| `pencil` | `#B3122E` | `#FF6B7D` | **только** расхождения |
| `amber` | `#8A5A00` | `#F2C46D` | нет значения |
| `green` | `#1F6B4A` | `#6FD3A0` | подтверждено / совпало |

У каждого статусного цвета есть «wash» для фона плашек. Цвет никогда не единственный носитель смысла: у плашек
есть текст.

**Шрифты** IBM Plex (Google Fonts, кириллица + казахские ә ғ қ ң ө ұ ү һ і): Sans — текст, Sans Condensed —
подписи и штампы, Mono — числа (`tabular-nums`). Шкала: 12 / 14 / 16 / 20 / 28 / 44 / 64.

**Геометрия.** Сетка 8 px, скругления 2–3 px, рамки 1 px, фокус — 2 px `blue`. Элементы управления не ниже
26 px (WCAG 2.5.8), контраст текста — AA.

**Компоненты** (`design/`): Button (primary / secondary / ghost), Badge (расхождение, нет значения, совпадает,
эксперту, скан), SectionChip (ПЗ / АР / КР / См.), Kbd, StampSummary (сводка-штамп), FindingRow,
PencilRing (обводка, рисуется как карандашом), Input, Select, Dialog, Toast, CommandMenu, EmptyState, Skeleton.

**Движение.** Интерфейс 150–250 мс, ease-out, без «пружин». `prefers-reduced-motion` — без анимации,
статичные кадры вместо сцены.

| 02 | Проблема | 2–3 факта о ручной сверке (счётчики) | этажи расходятся, проступают числа |

| 08 | Данные под контролем | доступ по приглашению · только свои проверки · удаление через 7 дней · документы не уходят в сторонние ИИ | — |
| 09 | Запросить доступ + подвал | форма: почта, организация, комментарий | — |

**Факты в тексте.** Цифры блоков 02 и 07 берутся из README и отчётов экспериментов на момент реализации и
согласуются с автором; выдуманных чисел нет.

**Сцена** (`landing/scene/`): react-three-fiber, геометрия генерируется кодом (линии `LineSegments`, без
моделей); 4 этажа-слоя, подписи и значения — HTML-оверлей (`drei/Html`, тот же шрифт IBM Plex); прогресс скролла 0…1 управляет
раздвижением, проявлением чисел и обводкой. Загрузка лениво (`React.lazy` + `Suspense`), первым рисуется текст.
Фолбэк — SVG-кадры «Расслоения» (тот же рисунок): при `prefers-reduced-motion`, ширине < 768 px или без WebGL.

**Языки.** Лендинг RU и KZ (словарь `lib/i18n`), выбор в шапке, запоминается. Казахские тексты пишутся сразу и
отмечаются на вычитку носителем.

## 5. Платформа

**Маршруты.**

| Путь | Вход | Экран |
|---|---|---|
| `/demo` | нет | демо-отчёт (статичные данные, §6) |
| `/login` | нет | вход, «Забыли пароль?», «Задайте пароль» (приглашение / сброс) — как сейчас |
| `/app` | да | мои проверки |
| `/app/new` | да | мастер новой проверки |
| `/app/checks/:id` | да | отчёт |
| `/app/settings` | да | почта, смена пароля, тема, выход |

Старая ссылка `/?check=<id>` перенаправляется на `/app/checks/<id>`.

**Оболочка.** Боковое меню (Проверки, Новая, Демо, Методика → блок 07 лендинга, Настройки), сверху поиск ⌘K и
почта пользователя. Локально (без Supabase) входа нет, оболочка та же.

**Мои проверки.** Таблица: название объекта (из ПЗ; можно переименовать), метки разделов, итог (≠ / нет
значения), прогресс эксперта, дата, срок хранения; строки «идёт проверка…» и «ошибка». Пустое состояние —
«Новая проверка» и «Демо».

**Новая проверка** — шаги «Файлы → Разделы → Проверка»: загрузка напрямую в хранилище с прогрессом по файлу
(как сейчас, `uploadFiles`), экран разделов (`FileReview`), запуск и ожидание. Ссылка на незавершённый шаг
возвращает к нему.

**Отчёт — три колонки.**
- Слева: вкладки «Замечания» / «ТЭП» / «Комплектность», фильтры (здание, что сверяется, признак, вердикт),
  счётчики.
- Центр: документы рядом / по одному, листание, масштаб, обводка (`RefPane`, как сейчас).
- Справа: панель замечания — значения по разделам и Δ %, вердикт «Подтверждаю / Ложное» (`1` / `2`),
  комментарий, примечания и цитаты из отчёта.
- Шапка: название, метки разделов, «Скачать XLSX», «Рядом / По одному», `?` (клавиши).
- Клавиши как сейчас: `j` / `k`, `←` / `→`, `s`, `1` / `2`, `?`.

**⌘K** (cmdk): переход к проверке и к замечанию по названию; действия «Новая проверка», «Скачать XLSX»,
«Тёмная тема», «Выйти».

**Переиспользуется**, а не пишется заново: `RefPane` / `Viewer` (PDF), фильтры и клавиши, вердикты, `export.ts`,
`FileReview`, `auth.ts`, `api.ts` — меняются вид и раскладка.

## 6. Данные и бэкенд

**Фронт.** TanStack Query: `useChecks()`, `useCheck(id)` (опрос, пока `pending` / `receiving`),
`useSaveReview()` (оптимистично, откат при ошибке; повторные нажатия по одному замечанию идут по очереди —
закрывает гонку из ревью), `useRenameCheck()`, `useAccessRequest()`.

**Демо без входа.** `scripts/export_demo.py` один раз строит отчёт по `data/synthetic/samples/ru/ru_00001/text`
и кладёт `demo-report.json` и PDF в `frontend/public/demo/`. Демо-отчёт и блок 04 читают их статикой;
сервер и вход не нужны.

**Бэкенд (добавления, анализ не меняется):**
- `GET /api/checks` — проверки владельца: `id, title, status, created_at, sections, summary, reviewed` (без
  отчёта целиком), новые сверху;
- `PATCH /api/checks/{id}` — `{title}` (1–200 символов), только владелец;
- `title` по умолчанию — объект из отчёта (`objects` / `pz_building`) или имя файла ПЗ;
- `POST /api/access-requests` — публичный: почта, организация, комментарий (ограничения длины),
  скрытое поле-ловушка; не более 5 заявок с одной почты в сутки;
- Supabase: колонка `checks.title`, таблица `access_requests` (RLS без политик — только сервер). Миграции —
  SQL-скриптом для SQL Editor (подключение Supabase в сессии отвалилось) или через подключение, если вернётся.

## 7. Ошибки, скорость, доступность

- Граница ошибок на каждый маршрут; ошибки сохранения — уведомления; 401 → `/login?next=…`, после входа —
  обратно.
- Бюджеты: стартовый JS лендинга ≤ 200 КБ gzip (без 3D); чанк 3D ≤ 250 КБ gzip, грузится лениво; платформа
  не грузит three.js.
- Доступность: AA по контрасту, рамки элементов ≥ 3:1, фокус виден, всё доступно с клавиатуры, у сцены есть
  текстовая альтернатива.

## 8. Тесты

- Vitest + Testing Library: фильтры, клавиши, очередь вердиктов, мастер, экспорт, i18n.
- Playwright (локальный бэкенд без входа): лендинг рендерится и фолбэк при `reduced-motion`; демо открывается;
  загрузка → разделы → отчёт → вердикт → XLSX; перенаправление `/?check=`.
- pytest: `GET /api/checks` (только свои), `PATCH` (только владелец, валидация), заявки (ловушка, лимит).
- Ручная проверка в браузере на 375 / 1366 / 1920 px и в обеих темах.

## 9. Порядок работ

1. **Основа:** маршруты, дизайн-система (токены, Tailwind, компоненты), оболочка, отчёт в три колонки на
   существующей логике.
2. **Платформа:** мои проверки (+ бэкенд `GET` / `PATCH`), мастер, ⌘K, настройки.
3. **Лендинг:** блоки 01–09 (тексты RU), сцена «Расслоение» и фолбэк.
4. **Демо и заявки:** `export_demo.py`, `/demo` и блок 04, заявки на доступ (+ бэкенд), KZ для лендинга.

Каждый этап — отдельные коммиты в `frontend-redesign`; в `main` вливается после проверки этапа.
